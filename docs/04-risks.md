# 04. 技術上の問題点とリスク

重大度：**高** = 着手前／Phase 1 で解決必須、**中** = 実装中に対処、**低** = 注記で足りる

---

## R1【高】高さ基準（標高 vs 楕円体高）のズレ

**問題**
CesiumJS の高さは**楕円体高**ですが、PLATEAU の建物・地形は**標高（ジオイド基準）**で作られています。
基準を取り違えると、**建物が地面から浮く／沈む**、あるいは花火の高度がずれる可能性があります。

> **公式ドキュメントの記載（2026-08-20 確認）**
>
> `https://docs.plateauview.mlit.go.jp/datasets/terrain/` に、PLATEAU-Terrain は
> 標高値にジオイドモデル（GSIGEO2011 など）を合成して**楕円体高に変換済み**であり、
> **「3D Tiles などのジオコード済みデータと垂直方向のずれが発生しないようになっている」**
> と明記されている。
>
> → PLATEAU-Terrain と PLATEAU-3DTiles の組み合わせは、公式には整合するとされている。
> ⚠️ **ただし公式の記述と実際の描画が一致するかは別問題**であり、D の実測は引き続き必須。
> また**ジオイドモデルはデータ生成時に固定**され、リクエスト時に切り替えられない。

⚠️ **ずれの量について、未検証の数値を前提にしないこと。**
「日本ではジオイド高の分だけ約 ○○m ずれる」といった数値をこのプロジェクトでは検証していません。
**ずれるかどうか、どの程度ずれるかは、必ず都南大橋周辺で実測して記録**してください
（[`05-verification-checklist.md` の D](05-verification-checklist.md#d-高さ整合の実測phase-1-の合否を左右する)）。

**方針**
- **PLATEAU-3DTiles と PLATEAU-Terrain を組み合わせる**（同じ出自のため整合が期待できるが、⚠️ 実測で確認する）。
- **Cesium World Terrain と PLATEAU-3DTiles を組み合わせると、高さがずれる可能性があります。**
  フォールバックとして使う場合は、D-2 で実測し、実測値を記録した上で扱いを決めること。
  ⚠️ 事前に「何 m ずれる」と決めつけない。
- Phase 1 の完了条件として、**都南大橋周辺で建物の足元が地面に接しているかを必ず目視確認**する。
- 「地上 1.6m」「高度 50〜300m」は絶対標高で持たず、
  **`sampleTerrainMostDetailed` で得た地盤高 + 相対高** として計算する（基準系の影響を受けにくい）。
- ズレが出た場合の対応：`tileset.modelMatrix` で全体を鉛直方向にオフセットし、
  オフセット値を設定ファイル化する（ただし**対症療法であることをコメントに明記**）。

## R2【高】盛岡市の建築物データの整備範囲・LOD が未確認

**問題**
会場（都南大橋下流）周辺に建築物モデルが無い場合、**遮蔽物のほとんどが表現できず、
アプリの価値が大きく下がる**。LOD1 しかない場合、屋根形状の差は再現できない。

**方針**
- Phase 0 で必ず確認（`05-verification-checklist.md`）。
- 無い場合は仕様を縮小し、**「会場周辺の建築物は未整備のため表示されていません」**と画面に明示する。
- LOD1 のみの場合、「屋根の形状は箱型に簡略化されています」と明示する。

## R3【高】配信サービスが「試験運用」であること

**問題**
PLATEAU 配信サービスは公式に「提供期間・サービスレベルを保証しない」「データや API スキーマは
予告なく変更される」と明記されています。URL が変わる、止まる、可能性があります。

**方針**
- 3D Tiles の URL・terrain のアセット ID を**すべて `src/config/plateau.ts` と `.env` に集約**し、
  コードに直書きしない。
- 複合 tileset.json API（`.../3dtiles/03201-bldg-lod1-latest/tileset.json`）が使えるなら、
  年度更新に自動追従できるので優先する。
- 読み込み失敗時は**アプリを落とさず**、「3D都市モデルの読み込みに失敗しました（配信元の一時的な問題の可能性）」
  と表示して地形のみで継続する。
- 長期運用するなら、G空間情報センターから CityGML / 3D Tiles を取得し
  （必要なら `PLATEAU GIS Converter` で変換して）**自前ホスティングに切り替えられる**構成にしておく。

## R4【中】Cesium ion トークン依存（**回避できる見込み**）

> ### ✅ 2026-08-20 更新：ion を使わない構成が可能
>
> 公式ドキュメントで、地形が **`https://tile.plateauview.mlit.go.jp/terrain/layer.json`** から
> **Cesium ion 非経由**で取得できることを確認した（公式が推奨する方式）。
> 建物は PLATEAU-3DTiles、背景は PLATEAU-Ortho または地理院タイルを使えば、
> **Cesium ion のアセットを一切使わない構成**にできる。その場合、本リスクは**該当しなくなる**。
>
> ⚠️ Step 4（最小 HTML）で「ion トークンを設定せずに地形・建物・背景がすべて表示される」ことを
> 実際に確認してから、正式に除外する。以下の記述は「ion を使う場合」に限定される。

**問題**
PLATEAU-Terrain は Cesium ion 経由で配信されており、公式チュートリアルに載っているのは**共有トークン**です。
これに依存したまま公開運用するのは望ましくありません。またチュートリアル内でアセット ID の記載が
2 種類（`3258112` / `2488101`）に分かれており、**どちらが現行かは未確定**です。
アセット ID は固定せず、最新公式ドキュメントまたは実アクセスで有効性を確認し、
採用した ID・確認日・確認方法を記録してください（`05-verification-checklist.md` の C）。

> **⚠️ 前提が変わった可能性（2026-08-20）**
>
> 公式ドキュメントによれば、PLATEAU-Terrain は現在**オブジェクトストレージからの直接配信
> （quantized-mesh、`/terrain/`）**が主であり、Cesium ion 経由は「従来方式」の位置づけ。
> **地形のために ion トークンが不要になる可能性が高い。**
> その場合、本リスク（R4）と GO/NO-GO 項目 8 は大幅に軽くなる。
> ⚠️ 実際の配信 URL と疎通は未確認（`05-verification-checklist.md` の C）。
> ion を使わない構成が確定したら、以下の記述は「ion を使う場合」に限定される。

**⚠️ 前提：Vite の `VITE_` 環境変数はブラウザに公開されます**

`import.meta.env.VITE_*` の値は**ビルド時にバンドルへ埋め込まれ、ブラウザの開発者ツールから
誰でも読み取れます**。`.env` に置いても、`.gitignore` してもこれは変わりません。
**トークンを「秘密にする」ことはできない**ため、**トークンでできることを最小化**する設計にします。

**方針**
- トークンは `.env`（`VITE_CESIUM_ION_TOKEN`）から読み込み、コードに直書きしない／リポジトリにコミットしない。
  （これは値を隠すためではなく、環境ごとに差し替えるためです）
- **権限（スコープ）を最小化する**：フロントエンド専用トークンを新規発行し、
  - `assets:read` のみを付与する。**`assets:write` / `assets:list` / `profile:read` などは付与しない**。
  - アクセス可能なアセットを、このアプリで実際に使うものだけに限定する（全アセット許可にしない）。
  - Cesium ion のデフォルトトークンを使い回さない。用途が分かる名前を付ける。
- **ドメイン制限をかける**：トークンに許可オリジン（allowed origins / referrer 制限）を設定し、
  自分のアプリのドメイン以外からは使えないようにする。
  **開発用（`localhost`）と本番用でトークンを分ける**。設定後、許可外ドメインから読めないことを確認する。
- **運用**：漏えい・不正利用時の失効（revoke）と再発行の手順を事前に確認しておく。
  無料枠の帯域・リクエスト上限と超過時の挙動も確認する。
- 公式チュートリアル記載の**共有トークンを本番で使わない**。
- 代替として、公式付録の `Cesium-Terrain-Builder` / `Cesium-Terrain-Server` による自前配信、
  もしくは Cesium World Terrain へのフォールバックを用意する。
- ⚠️ 上記をすべて行っても、**トークンは公開されたまま**です。
  残存する課金・不正利用のリスクを許容できるかを判断してから公開してください。
  許容できない場合は、地形を自前配信する構成（ion に依存しない）を選びます。
- 確認項目は [`05-verification-checklist.md` の E](05-verification-checklist.md#e-cesium-ion-トークンの安全設定ブラウザに公開される前提で設定する) にあります。

## R5【高】遮蔽（見通し）の自動判定は簡単ではない

**問題**
「花火が建物に隠れるか」を自動判定したくなりますが、CesiumJS の標準機能では困難です。

- `scene.clampToHeight` / `scene.pickFromRay` は **現在の視界に描画されている（＝ロード済みの）タイル**しか
  対象にしません。カメラの外や未ロードのタイルは無視され、**「遮蔽物が無い」と誤判定**します。
- 本格的な viewshed / line-of-sight 解析は **Cesium ion SDK（有償）** の機能です。

**方針**
- **第 1 版では自動判定を実装しない。** 「観覧者目線に立って、自分の目で確かめる」ツールとする
  （＝ユーザー要件の第 1 版機能一覧にも遮蔽判定は含まれていない）。
- 第 2 版で実装する場合の選択肢：
  1. **サンプリング法**：目線→花火のレイを N 分割し、各点で地形標高と比較（**地形の遮蔽のみ**判定可能。建物は不可）。
  2. **CityGML / 3D Tiles から建物ジオメトリを取り出し、CPU 側でレイキャスト**（正確だが実装コスト大、
     対象範囲を会場周辺に限定する必要あり）。
  3. **LOD1 の高さ属性を使った近似**：観覧地点〜打上地点の線上にある建物の「高さ」と「距離」から
     仰角を比較する（実装は現実的）。ただし **LOD1 は箱型に簡略化されたモデルであり、
     「建物による概略的な見え方の確認」の域を出ません**。個々の建物について
     見える／見えないを判定できる精度ではないことを、必ず明記します。
  4. `pickFromRay` を使う場合は、**判定前にカメラをその方向へ向けてタイルのロード完了を待つ**必要があり、
     UX が悪くなる。
- どの方式でも「樹木・電線・仮設物は判定外」であり、**判定結果を断定表現で出さない**。

## R6【中】河川敷の地形精度

5m メッシュ DEM 由来のため、堤防・護岸・河川敷の段差は平滑化されます。
会場（河川敷）と観覧地点（堤防上・市街地）の**高低差は数 m の誤差を含みます**。
→ 高低差の表示に「参考値（地形データは5mメッシュ由来）」と併記する。

## R7【中】打上地点の座標が非公表

主催者は打上地点の緯度経度を公表していません。**推定値**を使う以上、
距離・方位の計算結果には数十〜百数十メートル規模の誤差が入り得ます。
→ UI に「推定位置」バッジを常時表示。設定で座標を差し替えられるようにする。
→ 可能なら「打上地点をドラッグして動かせる」機能を付けて、ユーザー自身が調整できるようにする（第 2 版）。

## R8【中】Vite × CesiumJS のビルド設定

Cesium は `Workers/` `Assets/` `ThirdParty/` `Widgets/` の静的アセットを実行時に読み込みます。
`vite-plugin-cesium` を使うか、`vite-plugin-static-copy` でコピーして
`window.CESIUM_BASE_URL` を設定する必要があります。
→ Phase 1 の最初にここでつまずきやすいので、**まず「地球が回るだけ」の状態を作ってからデータを足す**。

## R9【中】描画パフォーマンス

3D Tiles ＋高精細 terrain は重く、モバイルでは特に苦しくなります。
→ `maximumScreenSpaceError` を上げる、建物タイルセットの表示範囲を会場周辺に絞る、
`requestRenderMode: true`（必要時のみ描画）を使う。夜モードの bloom は負荷が高いので設定で切れるようにする。
→ 対応環境（WebGL2 対応ブラウザ、推奨 PC）を明記する。

## R10【中】クリック地点の取得方法

- `camera.pickEllipsoid` は**地形を無視**するため使わない。
- 地形上の点は `scene.globe.pick(ray, scene)` が安定。
- 建物の屋上をクリックした場合は `scene.pickPosition`（深度バッファ利用）が必要だが、
  **屋上を観覧地点にするのは現実的でない**ため、第 1 版は「地面のみ」に限定してよい
  （その旨を UI に出す）。

## R11【中】交通規制情報の鮮度と権利

- 規制内容は毎年変わります。**年を明示し、古ければ警告**を出す。
- 公式の規制図（PDF 画像）を**そのまま転載しない**。公表内容を基に自分で作図する。
- 「概略であり、最新は主催者発表を確認」を必ず併記。

## R12【中】「安全側の設計」としての表現ルール

このアプリは人の行動（当日どこに行くか）に影響します。
- 「おすすめ」「穴場」といった**行動を誘導する表現を使わない**。
- 立入可否は判定できないことを、地点指定のたびに表示する。
- 交通規制区域内をクリックした場合は、警告を出す（規制 GeoJSON との交差判定は容易）。

## R13【低】方位の基準

`EllipsoidGeodesic.startHeading` は**真北基準**です。方位磁針（磁北）とは
盛岡付近で約 8〜9 度の偏角があります。→ 「真北基準」と明記する。

## R14【低】花火の見た目の忠実度

Cesium の `ParticleSystem` で花火らしい表現は可能ですが、
**実際の花火の開花直径・明るさ・残光を物理的に再現するものではありません**。
号数と開花直径の目安（例：3号≒約60m、10号≒約320m）を参考表示する場合も、
「目安」であることを明記します（打上プログラムは主催者発表を参照）。

## R15【低】ブラウザ対応

CesiumJS は WebGL2 前提の機能を多く使います。古い端末・WebGL 無効環境では動作しません。
→ 起動時に WebGL サポートを確認し、非対応時は分かりやすいメッセージを出す。

## R16【高】モデル上の「空っぽの河川敷」が誤認を生む

**問題（Phase 0 の実測で判明・2026-08-20）**

盛岡市の 3D 都市モデルでは、花火会場である都南大橋下流の北上川河川敷は
**建物も樹木も無い、完全に開けた空間**として描画される。
これはデータの不備ではなく、次の理由による。

- 河川敷に建築物が無いのは実態どおり。
- 盛岡市の植生データは **「植生モデル 単独木」**（`SolitaryVegetationObject`）のみで、
  面的な植被（`PlantCover`）を含まない。さらに会場周辺では単独木も表示されなかった。
  （同じレイヤーで盛岡市中心部の街路樹は正常に描画されるため、表示不具合ではなくデータ不在と確定）

一方、**実際の河川敷には草地・樹木・堤防沿いの並木があり、大会当日は仮設物・観覧者・車両が加わる。**
モデルをそのまま見せると、**「遮るものが何もない＝よく見える」と誤解させる**。
本アプリは人の当日の行動に影響するため、この誤認は実害につながり得る。

**方針**

- 会場周辺を表示している間は**常時**、「河川敷の草木・仮設物・当日の人や車は表示されていません」と明示する。
- 免責文に「**モデル上で開けて見えても、実際には遮るものがある場合があります**」を追加する。
- 「遮るものがありません」という断定表現を UI で使わない。
- 将来、遮蔽の簡易判定（R5）を実装する場合も、**河川敷の植生は判定対象外**であることを併記する。

## R17【高】LOD1 の高さは「点群の中央値」であり、建物の最高部ではない

**問題（Phase 0 の実測で判明・2026-08-20）**

盛岡市の建築物モデルの属性に
**`LOD1の立ち上げに使用する高さ：点群から取得_中央値`** と明記されている。

つまり LOD1 の箱の高さは、その建物の点群の**中央値**であり、**最高部ではない**。
屋根の棟、塔屋、パラペット、屋上の設備機器などは、箱の上にはみ出している。

**なぜ重大か**

遮蔽の観点では、これは **「実際には建物に遮られるのに、モデル上は遮られないように見える」**
という方向の誤差である。つまり **安全側ではない誤差**であり、
「見えるはず」と誤認させる方向に働く。R16（空っぽの河川敷）と同じ性質の問題。

**方針**

- 建物の高さは**過小に表現されている可能性がある**ことを、UI と免責文に明示する。
- 将来の遮蔽の簡易判定（R5 の案 3）で `計測高さ` や LOD1 の箱を使う場合、
  **判定結果を「見える」側に振らない**。境界的なケースは「判断できない」と表示する。
- LOD2 が利用可能なら、屋根形状が反映されるぶん LOD1 より実態に近い。
  ただし LOD2 でも塔屋・設備機器・アンテナまでは保証されない。
- 参考値として `計測高さ`（この建物では 15）も属性に存在するが、
  **これが最高部を意味するかは未確認**。断定して使わない。
