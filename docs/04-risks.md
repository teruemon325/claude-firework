# 04. 技術上の問題点とリスク

重大度：**高** = 着手前／Phase 1 で解決必須、**中** = 実装中に対処、**低** = 注記で足りる

---

## R1【高】高さ基準（標高 vs 楕円体高）のズレ

**問題**
CesiumJS の高さは**楕円体高**ですが、PLATEAU の建物・地形は**標高（ジオイド基準）**で作られています。
日本のジオイド高は 30〜40m 程度あるため、基準を取り違えると**建物が地面から大きく浮く／沈む**、
あるいは花火の高度が数十メートルずれます。

**方針**
- **PLATEAU-3DTiles と PLATEAU-Terrain を組み合わせる**（両者は同じ基準で作られており整合するとされる）。
- Cesium World Terrain と PLATEAU-3DTiles を混ぜない。
- Phase 1 の完了条件として、**都南大橋周辺で建物の足元が地面に接しているかを必ず目視確認**する。
- 「地上 1.6m」「高度 50〜300m」は絶対標高で持たず、
  **`sampleTerrainMostDetailed` で得た地盤高 + 相対高** として計算する（基準系の影響を受けにくい）。
- ズレが出た場合の対応：`tileset.modelMatrix` で全体を鉛直方向にオフセットし、
  オフセット値を設定ファイル化する（ただし**対症療法であることをコメントに明記**）。

## R2【高】盛岡市の建築物データの整備範囲・LOD が未確認

**問題**
会場（都南大橋下流）周辺に建築物モデルが無い場合、**遮蔽物のほとんどが表現できず、
アプリの価値が大きく下がる**。LOD1 しかない場合、屋根形状の差は再現できない。

**方針**
- Phase 0 で必ず確認（`05-verification-checklist.md`）。
- 無い場合は仕様を縮小し、**「会場周辺の建築物は未整備のため表示されていません」**と画面に明示する。
- LOD1 のみの場合、「屋根の形状は箱型に簡略化されています」と明示する。

---

## R3【高】配信サービスが「試験運用」であること

**問題**
PLATEAU 配信サービスは公式に「提供期間・サービスレベルを保証しない」「データや API スキーマは
予告なく変更される」と明記されています。URL が変わる、止まる、可能性があります。

**方針**
- 3D Tiles の URL・terrain のアセット ID を**すべて `src/config/plateau.ts` と `.env` に集約**し、
  コードに直書きしない。
- 複合 tileset.json API（`.../3dtiles/03201-bldg-lod1-latest/tileset.json`）が使えるなら、
  年度更新に自動追従できるので優先する。
- 読み込み失敗時は**アプリを落とさず**、「3D都市モデルの読み込みに失敗しました（配信元の一時的な問題の可能性）」
  と表示して地形のみで継続する。
- 長期運用するなら、G空間情報センターから CityGML / 3D Tiles を取得し
  （必要なら `PLATEAU GIS Converter` で変換して）**自前ホスティングに切り替えられる**構成にしておく。

## R4【高】Cesium ion トークン依存

**問題**
PLATEAU-Terrain は Cesium ion 経由で配信されており、公式チュートリアルに載っているのは**共有トークン**です。
これに依存したまま公開運用するのは望ましくありません。またチュートリアル内でアセット ID の記載が
2 種類（`3258112` / `2488101`）に分かれており、どちらが最新か要確認です。

**方針**
- トークンは `.env`（`VITE_CESIUM_ION_TOKEN`）から読み込む。リポジトリにコミットしない。
- 自分の Cesium ion アカウントのトークンを使う（無料枠の帯域上限に注意）。
- 代替として、公式付録の `Cesium-Terrain-Builder` / `Cesium-Terrain-Server` による自前配信、
  もしくは Cesium World Terrain へのフォールバックを用意する。
- ⚠️ フロントエンドに埋め込むトークンは**必ず公開される**。ion 側でドメイン制限を設定する。

## R5【高】遮蔽（見通し）の自動判定は簡単ではない

**問題**
「花火が建物に隠れるか」を自動判定したくなりますが、CesiumJS の標準機能では困難です。

- `scene.clampToHeight` / `scene.pickFromRay` は **現在の視界に描画されている（＝ロード済みの）タイル**しか
  対象にしません。カメラの外や未ロードのタイルは無視され、**「遮蔽物が無い」と誤判定**します。
- 本格的な viewshed / line-of-sight 解析は **Cesium ion SDK（有償）** の機能です。

**方針**
- **第 1 版では自動判定を実装しない。** 「観覧者目線に立って、自分の目で確かめる」ツールとする
  （＝ユーザー要件の第 1 版機能一覧にも遮蔽判定は含まれていない）。
- 第 2 版で実装する場合の選択肢：
  1. **サンプリング法**：目線→花火のレイを N 分割し、各点で地形標高と比較（**地形の遮蔽のみ**判定可能。建物は不可）。
  2. **CityGML / 3D Tiles から建物ジオメトリを取り出し、CPU 側でレイキャスト**（正確だが実装コスト大、
     対象範囲を会場周辺に限定する必要あり）。
  3. **LOD1 の高さ属性を使った近似**：観覧地点〜打上地点の線上にある建物の「高さ」と「距離」から
     仰角を比較する（LOD1 の箱型前提。実装は現実的。**近似であることを明記**）。
  4. `pickFromRay` を使う場合は、**判定前にカメラをその方向へ向けてタイルのロード完了を待つ**必要があり、
     UX が悪くなる。
- どの方式でも「樹木・電線・仮設物は判定外」であり、**判定結果を断定表現で出さない**。

## R6【中】河川敷の地形精度

5m メッシュ DEM 由来のため、堤防・護岸・河川敷の段差は平滑化されます。
会場（河川敷）と観覧地点（堤防上・市街地）の**高低差は数 m の誤差を含みます**。
→ 高低差の表示に「参考値（地形データは5mメッシュ由来）」と併記する。

## R7【中】打上地点の座標が非公表

主催者は打上地点の緯度経度を公表していません。**推定値**を使う以上、
距離・方位の計算結果には数十〜百数十メートル規模の誤差が入り得ます。
→ UI に「推定位置」バッジを常時表示。設定で座標を差し替えられるようにする。
→ 可能なら「打上地点をドラッグして動かせる」機能を付けて、ユーザー自身が調整できるようにする（第 2 版）。

## R8【中】Vite × CesiumJS のビルド設定

Cesium は `Workers/` `Assets/` `ThirdParty/` `Widgets/` の静的アセットを実行時に読み込みます。
`vite-plugin-cesium` を使うか、`vite-plugin-static-copy` でコピーして
`window.CESIUM_BASE_URL` を設定する必要があります。
→ Phase 1 の最初にここでつまずきやすいので、**まず「地球が回るだけ」の状態を作ってからデータを足す**。

## R9【中】描画パフォーマンス

3D Tiles ＋高精細 terrain は重く、モバイルでは特に苦しくなります。
→ `maximumScreenSpaceError` を上げる、建物タイルセットの表示範囲を会場周辺に絞る、
`requestRenderMode: true`（必要時のみ描画）を使う。夜モードの bloom は負荷が高いので設定で切れるようにする。
→ 対応環境（WebGL2 対応ブラウザ、推奨 PC）を明記する。

## R10【中】クリック地点の取得方法

- `camera.pickEllipsoid` は**地形を無視**するため使わない。
- 地形上の点は `scene.globe.pick(ray, scene)` が安定。
- 建物の屋上をクリックした場合は `scene.pickPosition`（深度バッファ利用）が必要だが、
  **屋上を観覧地点にするのは現実的でない**ため、第 1 版は「地面のみ」に限定してよい
  （その旨を UI に出す）。

## R11【中】交通規制情報の鮮度と権利

- 規制内容は毎年変わります。**年を明示し、古ければ警告**を出す。
- 公式の規制図（PDF 画像）を**そのまま転載しない**。公表内容を基に自分で作図する。
- 「概略であり、最新は主催者発表を確認」を必ず併記。

## R12【中】「安全側の設計」としての表現ルール

このアプリは人の行動（当日どこに行くか）に影響します。
- 「おすすめ」「穴場」といった**行動を誘導する表現を使わない**。
- 立入可否は判定できないことを、地点指定のたびに表示する。
- 交通規制区域内をクリックした場合は、警告を出す（規制 GeoJSON との交差判定は容易）。

## R13【低】方位の基準

`EllipsoidGeodesic.startHeading` は**真北基準**です。方位磁針（磁北）とは
盛岡付近で約 8〜9 度の偏角があります。→ 「真北基準」と明記する。

## R14【低】花火の見た目の忠実度

Cesium の `ParticleSystem` で花火らしい表現は可能ですが、
**実際の花火の開花直径・明るさ・残光を物理的に再現するものではありません**。
号数と開花直径の目安（例：3号≒約60m、10号≒約320m）を参考表示する場合も、
「目安」であることを明記します（打上プログラムは主催者発表を参照）。

## R15【低】ブラウザ対応

CesiumJS は WebGL2 前提の機能を多く使います。古い端末・WebGL 無効環境では動作しません。
→ 起動時に WebGL サポートを確認し、非対応時は分かりやすいメッセージを出す。
