> ### ⚠️ `LOD1 の立ち上げに使用する高さ = 点群から取得_中央値` の意味（重要）
>
> **LOD1 の箱の高さは、建物の最高部ではなく点群の中央値**である。
> つまり **LOD1 の箱は、実際の建物の最も高い部分より低い**可能性が高い
> （屋根の棟・塔屋・パラペット・設備機器は箱の上に出る）。
>
> 遮蔽の観点では、これは **「実際には遮られるのに、モデル上は遮られないように見える」** 方向の誤差であり、
> **安全側ではない**。→ `docs/04-risks.md` に **R17** として記録。

**その他の示唆**

- **`計測高さ` が個別建物に付いている** → 将来の遮蔽判定（`04-risks.md` R5 の案 3）で

### B-2-2. データセット名から分かること（2026-08-20）

  会場周辺で同じ表現が一切現れないことが、データ不在の根拠となる。

### B-2-3. ⚠️ 「空っぽの河川敷」による誤認リスク（重要）

会場周辺の河川敷は、3D 都市モデル上では**建物も樹木も無い完全に開けた空間**として描画される。
しかし**実際の河川敷には、草地・樹木・堤防沿いの並木・当日の仮設物・観覧者・車両が存在する**。

**このギャップをそのまま見せると、「遮るものが何もない＝よく見える」と誤解させる危険がある。**

対応（Phase 1 の必須要件とする）：

- 会場周辺を表示している間、**常時**「河川敷の草木・仮設物・当日の人や車は表示されていません」と明示する。
- 免責文に「**モデル上で開けて見えても、実際には遮るものがある場合があります**」を追加する。
- 「遮るものがありません」という表現を UI で使わない（`docs/03-data-and-license.md` の用語ルール）。

→ `docs/04-risks.md` に **R16** として記録。

## C. 地形（PLATEAU-Terrain）— **アセット ID を固定しない**

> **⚠️ この C は「あれば嬉しい」項目ではなく、地形の唯一の入手経路の確認です。**
> A の実測により、**盛岡市の地形（`dem`）は配信サービスの 3D Tiles / MVT カタログに存在しない**
> ことが判明しました。したがって本アプリの地形は **PLATEAU-Terrain（日本全国対象）** か、
> その代替（C-5）で賄うことになります。ここが通らないと高低差も目線高さも成立しません。

> ### ✅ 公式ドキュメントで判明した重要事項（2026-08-20）
>
> 出典：**`https://docs.plateauview.mlit.go.jp/datasets/terrain/`**（PLATEAU 配信サービス公式ドキュメント）
>
> **(1) Cesium ion を経由しない直接配信がある**
>
> > 現在配信しているのは、Cesium 向けの **quantized-mesh 形式の地形タイル（`/terrain/`）** です。
> > これは従来 Cesium ion 上でホストしていた PLATEAU-Terrain（5 章）をオブジェクトストレージに
> > ミラーし、そのまま配信しているものです。
>
> → **Cesium ion のアカウント・トークンなしで地形を読める可能性が高い。**
> 目次の「5. PLATEAU-Terrain (Cesium ion)」は**従来方式**の位置づけ。
> これにより `docs/04-risks.md` の R4（ion トークン依存）と GO/NO-GO 項目 8 の重みが下がる。
> ⚠️ ただし**実際の配信 URL と疎通は未確認**（→ C-2 で確認）。
>
> **(2) 標高は楕円体高に変換済みと公式に明記**
>
> > 国土地理院の基盤地図情報数値標高モデル（DEM）をはじめとした各種データソースから生成された
> > 標高値に、日本のジオイドモデル（GSIGEO2011 など）を合成し、**楕円体高（ellipsoidal height）**
> > に変換した地形を配信しています。これにより、**3D Tiles などのジオコード済みデータと
> > 垂直方向のずれが発生しない**ようになっています。
>
> → `docs/04-risks.md` の R1（高さ基準のズレ）について、公式が「ずれない」と明記している。
> ⚠️ ただし**公式の記述と実際の描画が一致するかは別問題**。D の実測は引き続き必須。
>
> **(3) ジオイドモデルは生成時に固定**
>
> > ジオイドモデルはデータ生成時に固定されており、リクエスト時に切り替えることはできません。
>
> → 高さ基準を後から変えることはできない。実測結果がずれた場合、アプリ側でのオフセット対応になる。

> ### ✅ C 完了（2026-08-20）— 採用方針が確定
>
> 出典：`https://docs.plateauview.mlit.go.jp/datasets/terrain/`
>
> **採用：Cesium ion を経由しない直接配信を使う。**
>
> ```
> https://tile.plateauview.mlit.go.jp/terrain/layer.json
> https://tile.plateauview.mlit.go.jp/terrain/{z}/{x}/{y}.terrain
> ```
>
> - 形式：**Cesium quantized-mesh-1.0**（TMS Geodetic、`octvertexnormals` 拡張付き）
> - 利用方法：`CesiumTerrainProvider.fromUrl` に `layer.json` の URL（または `/terrain`）を渡すだけ。
>   `requestVertexNormals: true` を指定すると法線付きで読み込める
> - **Cesium ion のアカウント・アクセストークンは不要**
> - 配信中のタイル一覧（カタログ API）：`https://tile.plateauview.mlit.go.jp/tiles/catalog.json`
>   （`name: terrain` / `urls` のキー `quantized-mesh` / URL `/terrain/layer.json`）
>
> **公式の注記**
> - 現在の `/terrain/` は**固定のジオイドモデルを適用済み**の quantized-mesh ミラー。
>   `?geoid=` を付与してもジオイドモデルは切り替わらない。

> **方針：アセット ID をこのドキュメントやコードに「正解」として固定しない。**
> 実装時点の**最新公式ドキュメント**、または**実アクセスによる疎通確認**で有効性を判定し、
> 判定結果と**確認日**を残す。値は `.env` / `src/config/plateau.ts` にのみ持たせる。

### D-3. 【項目 6】地形標高の妥当性（数値比較で判定）

> ### ⚠️ 最重要：そのまま引き算してはいけない
>
> - **PLATEAU-Terrain が返す高さ＝楕円体高（ellipsoidal height）**
>   （公式ドキュメントに「楕円体高に変換した地形を配信」と明記）
> - **地理院地図が表示する高さ＝標高（正標高）**
>
> この 2 つは基準が違う。そのまま引き算すると、日本国内ではジオイド高のぶん
> （数十 m 規模）の差が出るが、**それはズレではない**。比較は次の式で行う。
>
> ```
> 楕円体高（Cesium）  ≒  標高（地理院地図）  ＋  ジオイド高
> ```
>
> **ジオイド高は「どのジオイドモデルで計算したか」で値が変わる。**
> PLATEAU-Terrain が使ったモデルと違うモデルで計算した値を足すと、その差が誤差になる。
> 補正を入れずに「数十 m ずれている」と判定するのも誤り。

## F. 昼夜切替に必要なライティング設定の確認

> Cesium では**ライティングを明示的に有効化・調整する必要**があります。

| 設定 | 目的 | 確認 |
|---|---|---|
| `viewer.scene.globe.enableLighting = true` | 太陽位置に応じて地表を陰影づける（**既定は false**。これを入れないと夜でも地表が明るいまま） | [ ] |

| `viewer.scene.skyAtmosphere`（`show` / 明るさ） | 空の色。夜は暗くする | [ ] |
| `viewer.scene.sun` / `viewer.scene.moon` | 太陽・月の表示 | [ ] |
| `viewer.scene.light`（`SunLight` / `DirectionalLight`） | 3D Tiles（建物）への当たり方 | [ ] |
| `imageryLayer.brightness` / `gamma` | 夜モードで地表テクスチャを落とす | [ ] |
| 3D Tiles の `Cesium3DTileStyle`（`color`） | 夜モードで建物を暗くする | [ ] |
| `PostProcessStageLibrary.createBloomStage()` | 花火の発光表現（**負荷が高い**。ON/OFF を設定可能にする） | [ ] |

### 補足：この判定の考え方

- **1〜7 は「作っても意味がない／土台が壊れている」ことを防ぐための必須条件**です。
  特に 5（高さ整合）は、後から直すとアプリ全体の座標計算をやり直すことになるため、
  ここで必ず決着させます。
- **8・10 は「開発は進めてよいが、公開してはいけない」条件**です。
  権限設定と出典表記が未了のまま公開すると、課金リスクとライセンス違反につながります。
- **3 が NO-GO ではなく条件付き GO** なのは、建物が無くても
  「地形と遠方の建物による概略的な見え方の確認」というツールとしては成立するためです。
  ただしその場合は、**何が表示されていないのかを画面に明示**することが着手の条件です。
